# Capstone exercises

Read [the four capstone lessons](../lessons/15_capstone/01.md). Use documentation lookup, but attempt the reasoning and implementation before opening [solutions](../solutions/15_capstone.md). Record hints used; AI-written answers do not count as independent mastery.

## A. Specify the system

Draw the data/control flow from authenticated request to local action. For every boundary, state the input/output representation and whether the operation needs a provider request. List explicit behavior for unavailable evidence, incompatible current policies, another user's thread, and replay after approval. Explain why a third agent is or is not necessary.

## B. Recover and edit

Use a fresh thread, a human-authored draft, and separate processes. Start, exit, inspect, edit, and inspect again. Capture the pending state and final action text. Repeat the identical edit and verify one local action. Try a conflicting later decision. Explain the local transaction/identity invariant rather than merely reporting that an exception occurred.

## C. Verify rejection and isolation

Create a Bob-owned request and reject it. Show zero Bob actions. Attempt to inspect and resume an Alice-owned request as Bob; both must be denied without modifying Alice's state. Repeat after restarting the service/workflow process. Do not treat a client-supplied `user_id` as authentication.

## D. Diagnose evidence failures

Retrieve for an unopened-item return question, then for the remote-work allowance. Identify why obsolete `RETURN` v1 and two incompatible current remote-work sources require different treatment. Attempt a finance-only question as Alice and as finance. Separate permission filtering from semantic answer correctness.

## E. Evaluate one improvement

Declare the comparison protocol and trial count before running. Use development cases to choose exactly one change. Freeze the chosen configuration and run the held-out split. Report per-case retrieval outcomes, citation membership, claim support review, latency, usage, and limitations. If provider access is unavailable, run reachable deterministic checks and mark generated-answer findings unverified; do not fabricate a score.

## F. Transfer and teach

Change to a warranty question or add one synthetic current policy. Predict which components need changes, implement them, inspect evidence, and explain which invariants stay fixed. Write a clean-checkout tutorial and a limitations section. Distinguish local idempotency from external exactly-once delivery; explain how a disconnected client should safely investigate before retrying.

## Exit evidence

Practical behavior, your explanation, one diagnosed defect, and a fresh variation are required. Revisit the explanation and a new question later before claiming durable retention. Record peer/tutorial review only if it occurred. The user waived advisor review; do not invent sign-off or treat it as a remaining gate.
