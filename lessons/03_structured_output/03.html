03.3 — Compose stages only when their boundaries fit

Mission/objective: Advance the mission by tracing a Runnable/LCEL pipeline from input to a typed consumer result. Prerequisites: 03.2, prompt rendering; identify which invoke operation is local and which is remote.

Sources/version: RunnableSequence, PydanticOutputParser, ChatPromptTemplate. Checked 2026-10-12; installed authoring snapshot Python 3.14.0, langchain-core 1.6.9/Pydantic 2.14.1. Exact resolution is in uv.lock; actual execution evidence is in verification. Local composition is unpaid; the live pipeline invokes a model.

Retrieve first

Why retain original source text after rendering a prompt? What does a parsing error prevent the consumer from doing? Attempt before corrections.

Mental model and flow

LCEL's | passes one stage's output into the next stage's input. It does not make an incompatible function fit, catch every exception, or transform invalid data into facts. RunnableLambda adapts an ordinary function; a sequence supplies invoke/async/batch semantics. Many ordinary Lambdas buffer rather than transform streaming chunks, so composition does not automatically preserve token-by-token display.

The lab implements two honest compositions:

Check path Live path
authored JSON string {text: str}
PydanticOutputParser normalize exact input keys
source-evidence guard parallel source retention + prompt → structured model
SupportRecord inspect raw/parse envelope → source guard → consumer result

RunnableParallel here carries the original source on one branch and typed generation on another. It is not two competing model agents. The source branch is necessary because the evidence guard cannot validate a quote against an already-discarded source.

Worked example and guided fading

sequence = RunnableLambda(parser.parse) | RunnableLambda(check_source)
record = sequence.invoke(authored_json)

Run check mode and locate the returned typed fields. The authored fixture exercises parser/composition behavior, not a mocked model. Now complete a three-stage pipeline with input normalization before prompt rendering. Predict why {wrong_name: ...} fails before a remote call, and why a final guard must return the record rather than only printing it.

Failure investigation and independent variation

Change the guard's source to the missing-ID case while keeping the well-shaped authored record. The schema passes; the evidence guard rejects. This isolates stages more precisely than trying a new prompt. Attempt the changed-schema/source exercise in independent tasks, with solution withheld until your own diagram and attempt exist.
