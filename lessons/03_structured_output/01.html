03.1 — A valid shape can still contain an invented fact

Mission/objective: Advance the mission by defining required nullable fields and enforcing both schema and source-evidence boundaries. Prerequisites: Module 02, Pydantic basics; explain why an allowed classification label can still be incorrect.

Sources/version: Pydantic models, validators, model structured output. Checked 2026-10-12; installed authoring snapshot Python 3.14.0, Pydantic 2.14.1, langchain-core 1.6.9/langchain-openai 1.7.0. Exact resolution is in uv.lock; actual execution evidence is in verification. Local validation requires no model.

Retrieval warm-up

Does missing configuration mean a failed learning gate? What does strict JSON validation reject? Attempt before corrections.

Mental model and contract

The extraction lab returns SupportRecord, not an action. Every field is required, including nullable ones. order_id: str | None without a default means a caller must supply the field; null honestly represents unavailable information. A default invented identifier would destroy the boundary.

Field Meaning
status supported, unknown, contradictory or irrelevant
order_id one literal ORDER- identifier or null
category billing, technical, other or null
evidence_quote exact source substring containing the selected ID or null
reason nonblank explanation; not a claim of execution

Supported requires an ID, category and quote. Other statuses must not select an order or quote; irrelevant additionally has no category. A model validator enforces those relationships. A separate source guard rejects an absent ID, fabricated quotation and choosing one of multiple distinct source IDs. Multiple IDs are deliberately ambiguous under this lab's policy, even if a clever reader could infer a preferred one.

Worked example and guided completion

Check mode parses authored JSON for “Please refund order ORDER-104. I was charged twice.” It then validates the quote against the source. This is a parser/evidence demonstration, never an observed model answer. Provide the missing substring check in a separate function: both quote membership and ID membership inside the quote are necessary. A genuine substring unrelated to the chosen ID is insufficient.

Failure investigation and variation

Predict the difference between an omitted order_id, explicit null, malformed identifier and well-shaped invented identifier. The first three involve schema/consistency; the fourth needs source validation. Category relevance still requires human semantic review; substring checks do not prove the request should receive a refund. Attempt the missing/contradictory tasks in the exercise.

Exit and delayed review

Deliver a validated record, explicit unknown/contradiction/irrelevance or error—never a guessed record. Explain nullable versus optional and shape versus support. Review next week with a different identifier format, then apply evidence provenance in Module 07. Reference: glossary, runbook. Ask which boundary an apparently valid but invented value crossed.
