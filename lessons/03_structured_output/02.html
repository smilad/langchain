03.2 — Choose a structured-output strategy deliberately

Mission/objective: Support the mission by comparing model-level typed output with an agent's structured response and explaining capability requirements. Prerequisite: 03.1; identify the difference between a required null and a missing field.

Sources/version: models structured output, agent structured output, OpenAI integration. Checked 2026-10-12; installed authoring snapshot Python 3.14.0, LangChain 1.4.4/langchain-openai 1.7.0, Pydantic 2.14.1. Exact resolution is in uv.lock; verification separates four successful function-calling cases from rejected gateway JSON-schema output. Live paths require approved access supporting the selected strategy; the client requests temperature zero.

Recall first

Can JSON shape verify factual support? Is a requested tool call already an executed operation? Try before feedback.

Mental model and paths

Model-level with_structured_output(SupportRecord, …) wraps a model for typed responses. This lab chooses either provider JSON Schema or function-calling extraction. When invocation returns, include_raw=True supplies raw, parsed, and parsing_error; SDK/provider parsing errors can raise before that envelope exists. Check returned keys, then the source guard. A successful parsed object is not proof of a correct category.

An agent uses create_agent(..., response_format=...); its final state exposes structured_response alongside messages. ProviderStrategy requests provider-native schema enforcement. ToolStrategy represents the schema using model-requested function arguments. The schema function is an output representation, not permission to refund anything. Here tools=[]: there is no business side effect.

Worked example and guided completion

The lab implements both real paths:

uv run python labs/03_structured_output/main.py --live --method json_schema
uv run python labs/03_structured_output/main.py --live --engine agent --strategy tool

Each command sends a remote request path; an agent may need multiple turns. The tool strategy has handle_errors=False, and the agent has a recursion limit of eight. Complete the reasoning: if a typed result is absent, the consumer must ___ before accepting any record. Inspect actual messages/profile rather than assuming the requested strategy proves which provider mechanism was used.

Schema types can let the framework select a strategy from capability profiles. This lesson uses explicit strategies so the choice is visible. Model profiles, provider schema subsets, refusals and simultaneous tool/schema support vary; there is no universal adapter guarantee. An unsupported capability should surface as an explicit error, not a fabricated response or silent fake fallback.

Failure investigation, transfer and exit

Predict unsupported JSON Schema versus parsing failure versus a valid contradictory record. Only the first is a capability mismatch. Try both permitted methods on approved synthetic input if your model supports them; otherwise mark that live branch unverified in the exercise. Exit by locating typed data and raw evidence in each envelope. Review in Module 04 when actual tools enter an agent. Reference: API map, runbook. Ask about a named strategy, capability and error class.
