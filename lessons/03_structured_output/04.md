# 03.4 — Stop impossible extraction instead of retrying it into fiction

**In plain words:** Sometimes the right answer is "unknown" or "contradictory". Retrying cannot create information that is not in the input, so stop and report the failure instead of forcing a made-up answer.

**Mission/objective:** Serve the [mission](../../MISSION.md) by diagnosing unsupported capability, malformed shape and semantic impossibility separately, then returning an explicit bounded outcome. Prerequisites: [03.1](01.md)–[03.3](03.md); draw the input→prompt→model→parse→source-validation path.

**Sources/version:** [structured-output error handling](https://docs.langchain.com/oss/python/langchain/structured-output#error-handling), [OpenAI structured outputs](https://platform.openai.com/docs/guides/structured-outputs), [Pydantic validators](https://docs.pydantic.dev/latest/concepts/validators/). ## Recall first

## Mental model and failure ladder
The [lab](../../labs/03_structured_output/main.py) defines four synthetic inputs: complete order, missing order, two contradictory identifiers and irrelevant poetry request. Unknown is a valid domain outcome, not broken formatting. Contradictory deliberately forbids choosing a convenient identifier; irrelevant must not acquire a fabricated support category.

| Failure stage | Appropriate next action |
|---|---|
| missing/blank input | obtain input; no request is sent |
| unsupported API/schema method | check chosen model/integration capability |
| timeout/429 | inspect transport/quota; retain bounded retry policy |
| parse or shape error | inspect raw envelope and schema |
| absent quote/ID | reject; do not accept a guessed fact |
| missing source information | return unknown or ask a human for information |

## Worked example and guided decision
Check mode supplies an authored supported record to a source without its identifier and then to the conflicting source. The guard raises actual ValueError in both cases. The printed report is a caught diagnostic, not an invented model outcome. In live model mode, `parsing_error` or missing `parsed` stops consumer delivery. Agent tool strategy disables automatic structured-output retries and uses a recursion bound; provider transport still has one configured retry.

Complete this decision in your own variation: if no order identifier exists, repeatedly requesting a schema-valid ID is ___ because ___. A correction request may repair a formatting mistake, but cannot add absent evidence. Refusal or incomplete responses should be inspected and treated as explicit failures, never mapped to a successful support record.

## Independent investigation and exit
Run each local boundary and predict its stage before execution. If access permits, choose the four live cases one at a time; review category/relevance yourself and record actual envelopes. Try an unfamiliar missing-data request from the [exercise](../../exercises/03_structured_output.md), not a copy of the worked input. Exit with a defensible record/error/abstention policy, evidence against invention and a diagnosis for capability mismatch.
