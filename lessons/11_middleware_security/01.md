# 11.1 — Middleware controls calls; it does not replace domain authorization

**In plain words:** Middleware can block a tool call, but the tool itself must still check permission, because code can call it without the agent. Defense belongs where the action is executed.

[Mission](../../MISSION.md). **Objective:** locate the tool-execution hook and explain what remains protected if that hook is bypassed.

## Prerequisites and warm-up
Modules 04, 08 and 10. Who requests a tool call, and who executes it? Where is thread ownership stored? Does an approval prompt grant permission? Attempt answers before reading the security implementation.

## Mental model
A node-style hook runs before/after a stage; a wrap-style hook encloses a particular model or tool call and chooses whether to invoke its handler. Authorization belongs before tool execution. Middleware can deny a call while returning a `ToolMessage` so the model receives a bounded, non-sensitive explanation.

[security.py](../../src/langchain_learning/security.py) implements `AuthorizationMiddleware.wrap_tool_call`. It reads authenticated runtime context, tool name and model-proposed arguments. `authorize_call` grants only `inspect_thread`, validates a schema rejecting extra arguments, and checks the thread against immutable owner metadata. Unauthorized calls return a denial message rather than exposing the requested state.

## Worked integration
`build_security_agent()` uses actual `create_agent`, one read-only tool, custom middleware and call-limit middleware. `SecurityContext` carries the trusted local identity and database paths. `ToolRuntime` injects it into the tool; the model cannot choose runtime identity through its argument schema.

Run `uv run python labs/11_middleware_security/main.py --check` for real domain-boundary checks. Then, with configured model and consent, run `--live` to observe actual model/tool messages through middleware. Distinguish model refusal, denied tool execution and no attempted attack. None is equivalent to broad injection immunity.

## Guided completion and failure diagnosis
Predict what would happen if the tool trusted middleware but its Python function performed no ownership check. A direct caller could bypass the hook. Here the tool calls the same authorization function again, and the workflow checks ownership independently. The repeated check is intentional defense at the execution boundary, not permission derived from a prompt.
