11.2 — Bound execution and minimize what enters context

Mission. Objective: identify which budgets actually stop work and which private fields are excluded from a tool response.

Prerequisites and recall

Middleware hooks, Module 05 context selection and Module 08 latency/cost distinctions. Can a recursion limit bound input size? Can redacting a final answer undo a secret already sent to a provider? Attempt both before inspecting the code.

Sources and version note

Built-in middleware and tool runtime context, checked 2026-10-12. Installed baseline: Python 3.14.0, LangChain 1.4.4, LangGraph 1.2.14, langchain-openai 1.7.0; lockfile, exercised evidence. Budget APIs and provider capabilities must match the installed lock.

Mental model

Different budgets constrain different resources. The security agent permits at most three model calls and three tool calls per run, and uses a graph recursion bound. A model-call budget is not a dollar cap, a context-size cap, or protection against one expensive request. Provider timeout/retry settings come from the course runtime; their purpose differs from graph termination.

The secure tool returns only thread ID, status, pending-review count and action count. It excludes questions, draft bodies, owner identifiers, documents and database paths. This is data minimization before transmission. Raw checkpoint dumps would contain much more than the model needs for a status question.

Worked example

Inspect authorized_inspect in security.py. Compare its four-field result with SupportWorkflow.inspect from Module 10. The application can inspect rich state locally; a model receives the narrow projection required for its task.

Run uv run python labs/11_middleware_security/main.py --check. The allowed alice-thread call returns only that projection. In live mode examine tool messages, call counts and final claims. If the agent never uses its available tool, do not report successful tool execution merely because the final answer sounds plausible.

Guided completion and diagnosis

List fields you would remove before adding another tool. In an exercise copy, ask repeated status questions and compare the run budget with accumulated conversation length. Explain why reducing a call budget does not make previously retained context private. If a secret appears in a model response, inspect the outbound messages and tool results before adding redaction at the final display boundary.

Independent gate and review

Exercise: propose a narrow read-only capability and explicit budget rationale. Demonstrate the projection, diagnose one overbroad response, and state what each budget cannot guarantee. During Module 14 evaluate actual latency and capacity rather than inventing an SLA from these teaching limits. Solutions.
