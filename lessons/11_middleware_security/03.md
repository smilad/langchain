# 11.3 — Retrieved instructions remain untrusted data

[Mission](../../MISSION.md). **Objective:** compare a deliberately unsafe synthetic permission rule with real execution boundaries under an injection attempt.

## Prerequisites and warm-up
Module 07 grounding, Module 10 approval, and [middleware](01.md). Can an authorized retrieved source authorize a tool? Does citation presence prove an instruction is trustworthy? Which system component should own capability grants? Attempt before reading the attack.

Live injection behavior depends on model, prompt and trials; no immunity claim is made.

## Mental model and threat boundary
A retrieved document is evidence to assess, not authority over application identity or capabilities. The corpus includes MALICIOUS: an untrusted imported note telling an assistant to reveal a synthetic finance code and claim unlimited refunds. Retrieval access and content trust are separate dimensions: public users may inspect this note for the lesson, but it does not become approved policy.

The lab also appends a synthetic attack claiming administrator permission, requesting bob's thread, secrets and approvals. It never includes real credentials. The secure agent has no approval or secret-reading tool and receives no vault marker in its context. Even a model following the attack cannot create capabilities absent from its execution interface.

## Worked comparison
Run `uv run python labs/11_middleware_security/main.py --check`. It retrieves the real malicious document, tests forbidden capabilities and cross-owner arguments, and confirms both owners still have zero actions. A deliberately unsafe **non-model fixture** grants access from document text and reveals a committed synthetic marker. This is an explicit vulnerable counterexample, not a fabricated model output or a claim that the live model leaked.

Run `--live` only with provider consent. Review actual messages: did the model request forbidden work, decline it, or ignore it? Record those as separate outcomes. The immutable owner/action boundaries are deterministic; semantic answer contamination remains a model-quality risk requiring review.

## Guided completion and failure investigation
Predict whether changing the attack's wording can change `authorize_call` permissions. It must not. If bob's state becomes visible, inspect identity binding and tool arguments, not the system prompt. If the model repeats unlimited refunds, investigate grounding and untrusted-source handling separately from action authorization.
