# 11.2 — Bound execution and minimize what enters context

[Mission](../../MISSION.md). **Objective:** identify which budgets actually stop work and which private fields are excluded from a tool response.

## Mental model
Different budgets constrain different resources. The security agent permits at most three model calls and three tool calls per run, and uses a graph recursion bound. A model-call budget is not a dollar cap, a context-size cap, or protection against one expensive request. Provider timeout/retry settings come from the course runtime; their purpose differs from graph termination.

The secure tool returns only thread ID, status, pending-review count and action count. It excludes questions, draft bodies, owner identifiers, documents and database paths. This is data minimization before transmission. Raw checkpoint dumps would contain much more than the model needs for a status question.

## Guided completion and diagnosis
List fields you would remove before adding another tool. In an exercise copy, ask repeated status questions and compare the run budget with accumulated conversation length. Explain why reducing a call budget does not make previously retained context private. If a secret appears in a model response, inspect the outbound messages and tool results before adding redaction at the final display boundary.
