# 15.2 — Run the baseline and recover a paused review

**In plain words:** Run the whole system locally, pause at the review step, restart the process, and resume. Check that a repeated approval records one action and that another user is denied.

**Objective:** distinguish a locally verified control path from a live, model-generated draft, and recover a pending review without duplicating an approved local record.

**Prerequisites:** [capstone architecture](01.md), [interrupt/resume](../10_durable_approval/02.md), and environment setup. Use the versions in [the verification report](../../docs/VERIFICATION.md); the lab uses the real `SupportWorkflow`, SQLite checkpointing, and retrieval implementation.

## Recall and prediction

Before running anything, sketch which information must persist while a review is paused. Predict what an in-memory checkpointer would do after the process exits. Finally, decide whether a rejected proposal should leave an action in the sink.

## First run: real local behavior, no model claim

```bash
uv run python labs/15_capstone/main.py --check
```

The check reads real policy documents and exercises two users against real persisted graph state. The draft is explicitly human-authored exercise text. It closes/reopens SQLite connections, resumes an edit, repeats that decision, rejects another thread, and attempts a cross-user inspection. Read the emitted evidence. It must say that a model request was not sent; a successful local check is not a RAG-quality evaluation.

Connection reopening demonstrates a persistence mechanism. For process-restart evidence, use separate invocations:

```bash
uv run python labs/15_capstone/main.py --action start --thread learner-review \
  --draft 'Human-authored draft: verify RETURN v2 and its conditions before replying.'
uv run python labs/15_capstone/main.py --action inspect --thread learner-review
uv run python labs/15_capstone/main.py --action edit --thread learner-review \
  --edited-draft 'The current return policy requires an unused item and receipt; confirm delivery date.'
uv run python labs/15_capstone/main.py --action inspect --thread learner-review
```

Each command starts a new process. Inspect the pending review before the decision and the recorded action afterward. Repeat the exact edit and check that the existing local record is reused. A conflicting later decision is an error, not a second approval opportunity.

## Live baseline

Configure `OPENAI_API_KEY`, `COURSE_MODEL`, and explicit `COURSE_ALLOW_LIVE=1` only after choosing a provider budget. Then run:

```bash
uv run python labs/15_capstone/main.py --live --action start --thread live-return
```

The model draft must remain paused. Inspect its sources and substantive claims before approving. Transport success, schema validation, and citation membership are separate from factual support. The course does not approve the live draft merely because it parsed.

## Fade support and transfer

Now create a Bob-owned thread and reject it without copying the example commands. Next attempt to inspect Alice's thread as Bob. Explain the expected exception and show evidence that Bob's action list stays empty.

For a failure investigation, change only the thread ID during resume. Determine whether you selected a different workflow, not whether the provider “forgot.” Locate the thread/identity boundary before considering prompt changes.

**Exit check:** demonstrate restart, edit, rejection, repeat-decision idempotency, and ownership denial. Name the remaining live-quality checks honestly. Repeat the same control experiment with a fresh thread next session.
