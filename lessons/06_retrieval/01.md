## Mental model
A loader converts an external representation into text plus metadata; it does not certify the text. Our loader reads JSON policy records instead of adding a PDF dependency for a corpus that is already structured. A LangChain Document carries page_content, metadata and an optional id. Keep source_id separate from chunk_id: RETURN names the policy, while RETURN:v2:0 locates one passage in one revision. Provenance identifies a synthetic author or imported attachment; audience controls eligibility; trust distinguishes approved policy from an injection exercise.

The source directory deliberately includes RETURN v1 and v2. Retaining history for inspection is not permission to answer from history. PolicyIndex.documents includes ingested history, but authorized_documents supplies only current records in the caller's audience. Schema validation rejects missing metadata, invalid audiences and duplicate current source IDs. It does not decide whether two differently named current policies contradict one another. Inspect REMOTE and REMOTE-EXCEPTION to see that distinction.

Do not embed everything and filter only the final answer. That design may already have sent private source text to a provider or let it influence ranking. Here authentication-derived identity is checked before selecting eligible documents. The tiny identity map is a teaching boundary, not production authentication. MALICIOUS remains public untrusted data to exercise instruction handling; finance text never reaches public retrieval.

## Data/control flow
`JSON bytes → validated records → Document(text, metadata, id) → authorized current candidates`

## Worked example
Run from the repository root after `uv sync --locked`. This is implemented code/command guidance, **not an observed output**:

```python
from langchain_learning.retrieval import PolicyIndex
index = PolicyIndex()
for doc in index.authorized_documents("alice"):
    print(doc.id, doc.metadata["source_id"], doc.metadata["provenance"])
```
