# 12.4 — Keep or reject the specialist with evidence

**Mission/objective:** serve [the mission](../../MISSION.md) by publishing a defensible single-agent versus specialist comparison, including failed trials instead of averaging them away.

**Prerequisites:** [handoff contracts](03.md) and evaluation splits. Check: distinguish an unknown token count from zero tokens.

**Sources/version:** [LangChain evaluation concepts](https://docs.langchain.com/langsmith/evaluation) and [subagent tradeoffs](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents), checked 2026-10-12. Installed baseline Python 3.14.0, LangChain 1.4.4, LangChain OpenAI 1.7.0; [lockfile](../../uv.lock) is authoritative and [verification](../../docs/VERIFICATION.md) records actual runtime evidence. No live scores, costs, or latency targets are invented when provider prerequisites are unavailable.

## Warm-up
Why freeze held-out inputs? Why include failures in a comparison? Correction after attempting: tuning on evaluation cases biases claims; failures affect usefulness and cost even when no final answer exists.

## Experiment design
Both arms see the same original question, identity, and filtered evidence. Trial order alternates to reduce simple warm-up/order confounding. The lab's four cases include answerable policies, unavailable information, and restricted finance information requested by a public identity. These are a teaching sample, not a statistically powerful benchmark and not a replacement for the frozen Module 08 held-out set.

Every row reports wall-clock latency, attempted logical model/tool calls, provider usage when present, source-membership validation, and either a draft or a sanitized error type. Nested calls belong in the total. SDK retries, missing provider usage, and failed calls complicate cost; do not multiply an unknown count by today's price and call it observed cost.

## Worked review
Run `uv run python labs/12_multi_agent/main.py --live --trials 2`, retaining its actual JSON rows locally. Build a table per case and arm. Review each draft against the retrieved passages: supported claims, handling of contradictions, appropriate abstention, no restricted disclosure, and resistance to document instructions. Record reviewer decisions explicitly; the lab does not manufacture human judgments.

Compare latency distributions and variability alongside quality. A specialist that increases runtime while merely paraphrasing the same evidence has not earned its complexity. Rejecting it is a valid course result.

## Guided and independent work
Supply a missing failure row in your comparison table from an actual run, not an imagined output. Then follow [the independent exercise](../../exercises/12_multi_agent.md): change one context constraint and rerun a declared trial count without retuning on held-out cases.

## Failure diagnosis, exit, review
If all specialist trials fail, separate configuration, transport, budget, schema, and membership failures before adjusting prompts. Exit with a written keep/reject decision tied to measured rows and limitations. Revisit the decision in [Module 15](../15_capstone/03.md); [solutions](../../solutions/12_multi_agent.md) show reasoning, not a universal winning architecture.
