12.2 — One specialist, not a zoo of agents

Mission/objective: support the mission by implementing and explaining one synchronous subagent-as-tool pattern. Distinguish it from a router, handoff, and supervisor without implementing four architectures.

Prerequisites: the baseline and tool argument/execution boundaries. Check: who decides whether a requested tool runs?

Sources/version: official subagent patterns and multi-agent overview, checked 2026-10-12. Installed baseline Python 3.14.0, LangChain 1.4.4, LangChain OpenAI 1.7.0; lockfile records dependencies and verification records exercised behavior. Live proof requires consent and a tool-capable, structured-output model; no generated output is invented in its absence.

Retrieval warm-up

Before reading, name the owner of user identity and explain why another agent cannot authorize an action. Correction: application authentication owns identity; model-generated intentions are proposals.

Pattern vocabulary

A router chooses a destination, often once. A handoff transfers active conversational responsibility. A supervisor keeps central control and can delegate repeatedly. Our narrower experiment gives a central agent exactly one specialist tool and permits at most one invocation. The specialist is another actual create_agent, not a Python function renamed “agent.” It has its own prompt and retrieval tool; the supervisor has neither direct retrieval nor action tools.
