# 12.2 — One specialist, not a zoo of agents

**In plain words:** The simplest multi-agent pattern is a coordinator that can call one specialist as a tool. You limit it to one call and give it only the question, so it cannot widen what it can see.

**Mission/objective:** support [the mission](../../MISSION.md) by implementing and explaining one synchronous subagent-as-tool pattern. Distinguish it from a router, handoff, and supervisor without implementing four architectures.

**Prerequisites:** [the baseline](01.md) and tool argument/execution boundaries. Check: who decides whether a requested tool runs?

**Sources/version:** [official subagent patterns](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents) and [multi-agent overview](https://docs.langchain.com/oss/python/langchain/multi-agent), checked 2026-10-12. ## Pattern vocabulary
A **router** chooses a destination, often once. A **handoff** transfers active conversational responsibility. A **supervisor** keeps central control and can delegate repeatedly. Our narrower experiment gives a central agent exactly one specialist tool and permits at most one invocation. The specialist is another actual `create_agent`, not a Python function renamed “agent.” It has its own prompt and retrieval tool; the supervisor has neither direct retrieval nor action tools.

| Stage | Receives | Returns |
|---|---|---|
| Coordinator | Original question | Structured final draft |
| Specialist tool | Question only | Validated JSON findings |
| Specialist agent | Question and request-scoped policy tool | GroundedAnswer |

No hidden conversation transcript is shared. The question passed by the coordinator cannot broaden the frozen retrieval scope. This favors isolation over dynamic search; state this limitation when interpreting quality.
