12.1 — Earn the second agent

Mission/objective: advance the mission by deciding whether another model-driven component solves a measured problem. Explain and execute the single-agent baseline before adding a specialist.

Prerequisites: evaluation, graph termination, and authorization. Check: distinguish a model call, a tool call, and a graph step.

Sources/version: LangChain subagents, checked 2026-10-12. Installed baseline Python 3.14.0, LangChain 1.4.4, LangChain OpenAI 1.7.0; exact dependencies in uv.lock, runtime evidence and limits in verification. Live agents require configured OpenAI-compatible tool calling, structured output, model ID, key, and explicit paid-call consent. Live model proof is unavailable without those prerequisites.

Recall before reading

  1. Does a valid citation identifier prove support?
  2. Can a tool description grant authorization?

Correction after attempting: neither. Inspect the actual evidence and enforce identity outside the prompt.

Mental model and flow

The baseline is one create_agent with a request-scoped retrieval tool. Application code binds identity and freezes the retrieved evidence for both experimental arms. The agent drafts a GroundedAnswer; membership validation checks citations against that evidence. No arm approves or sends anything.

question + authenticated identity → filtered evidence → agent/tool loop → typed draft → validation → human quality review

This deliberately limits the experiment to Project C's drafting stage. Durable review remains the workflow's responsibility; adding a second agent does not change permission to execute an action.

Worked example

Run uv run python labs/12_multi_agent/main.py --check. It really retrieves policy documents and rejects an invalid citation handoff, but generates no model answer. Then, with live configuration, run --live --trials 2. Each printed row identifies its arm, case, trial, evidence, elapsed time, call counts, reported usage, and failure category. These are runtime records, not published example scores.

Guided completion and transfer

Explain why removing the frozen evidence boundary would confound the comparison. Supply the missing final check in a copy of validate_handoff: a non-abstaining answer needs at least one authorized evidence ID. Change one question using the exercise, not the architectural variables simultaneously.

Failure investigation and exit

Predict what happens when a model answers without calling retrieval. The application rejects a bypassed boundary; fluent prose is not success. Exit by tracing one real row and identifying which quality claim still needs human review. Revisit this decision in Module 15; consult the glossary for agent versus workflow. Ask: which observed defect would justify delegation?
