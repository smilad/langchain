# 12.1 — Earn the second agent

**Mission/objective:** advance [the mission](../../MISSION.md) by deciding whether another model-driven component solves a measured problem. Explain and execute the single-agent baseline before adding a specialist.

**Prerequisites:** [evaluation](../08_evaluation/04.md), [graph termination](../09_graph_workflows/02.md), and [authorization](../11_middleware_security/04.md). Check: distinguish a model call, a tool call, and a graph step.

**Sources/version:** [LangChain subagents](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents), checked 2026-10-12. Installed baseline Python 3.14.0, LangChain 1.4.4, LangChain OpenAI 1.7.0; exact dependencies in [uv.lock](../../uv.lock), runtime evidence and limits in [verification](../../docs/VERIFICATION.md). ## Mental model and flow
The baseline is one `create_agent` with a request-scoped retrieval tool. Application code binds identity and freezes the retrieved evidence for both experimental arms. The agent drafts a `GroundedAnswer`; membership validation checks citations against that evidence. No arm approves or sends anything.

`question + authenticated identity → filtered evidence → agent/tool loop → typed draft → validation → human quality review`

This deliberately limits the experiment to Project C's drafting stage. Durable review remains the workflow's responsibility; adding a second agent does not change permission to execute an action.

## Worked example
Run `uv run python labs/12_multi_agent/main.py --check`. It really retrieves policy documents and rejects an invalid citation handoff, but generates no model answer. Then, with live configuration, run `--live --trials 2`. Each printed row identifies its arm, case, trial, evidence, elapsed time, call counts, reported usage, and failure category. These are runtime records, not published example scores.

Exit by tracing one real row and identifying which quality claim still needs human review.
