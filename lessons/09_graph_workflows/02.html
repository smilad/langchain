09.2 — Routing is a decision plus a termination contract

Mission. Objective: run every conditional route and diagnose a graph that never terminates.

Prerequisites and warm-up

Read state contracts. Predict whether changing a state value changes an edge automatically. Recall why an agent needs a run bound, and why validated model output can still represent a bad decision. Attempt answers before consulting Module 03 or 04.

Sources and compatibility

Conditional edges and termination, checked 2026-10-12. Installed baseline: Python 3.14.0, LangGraph 1.2.14, LangChain 1.4.4, Pydantic 2.14.1; lockfile, exercised evidence. Check mode is deterministic graph execution. Live requires provider structured output and consent; routing fixtures do not cover that gate.

Mental model

A classifier writes a route label. A routing function maps that label to node names. A terminal branch reaches END; a supported branch fans out then joins. The label is data; edges are control flow. Confusing them creates graphs that hold a sensible classification but execute the wrong work.

The lab deliberately uses explicit rules before introducing a model. Questions containing return take the supported path; escalate takes review; other text takes unsupported. These narrow fixtures are not a general classifier and are not generated answers. Their purpose is to exercise all paths predictably.

Worked example

Run uv run python labs/09_graph_workflows/main.py --check. Find classify's partial update and follow its destination. Review and unsupported each terminate immediately. Supported runs retrieve and constraints, waits for both, then drafts. The printed draft is labeled human-authored routing exercise text.

With explicit provider configuration, run uv run python labs/09_graph_workflows/main.py --live --question 'What is the return policy?'. Classification invokes a real model with a Route Pydantic schema. A supported decision then uses real rag.answer. The model may choose another valid route: record that as a classification outcome, not a framework failure.

Guided completion and failure investigation

Predict the result of an edge from a node back to itself. Check mode constructs this actual faulty graph with recursion limit three and requires GraphRecursionError. The limit is a last-resort bound, not evidence of valid termination. Repair the graph by defining a stopping condition or directing terminal work to END, not by increasing the limit indefinitely.

Transfer and exit

In the exercise, vary wording and propose a route matrix before execution. Explain when deterministic classification is preferable, and where model variability enters. Pass by running all paths, explaining termination, diagnosing the loop, and handling an unfamiliar request. During Module 12 compare this fixed router with a specialist router; use solutions only after your attempt.

Reference: API map and glossary. Focused follow-up: which request would expose your router's weakest assumption?
