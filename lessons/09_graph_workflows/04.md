# 09.4 — Fan-out requires a meaningful fan-in

**In plain words:** Run independent steps in parallel, then join them with one edge that waits for all of them. Parallelism is only safe when the branches do not depend on each other.

[Mission](../../MISSION.md). **Objective:** show that a draft waits for two independent branches, then distinguish deterministic graph proof from live model-routing proof.

## Mental model and worked flow
The supported route returns two destinations, retrieve and constraints. They execute in the same super-step, contribute events using the reducer, and join through `add_edge(['retrieve', 'constraints'], 'draft')`. The list-of-start-nodes edge is a barrier: draft should not proceed after just one contributor.

Retrieve accesses the real filtered policy corpus. Constraints contributes the read-only policy event. It is deliberately small and deterministic; there is no fake external compliance service. Draft in check mode records explicit human exercise text. In live mode the graph invokes actual structured model classification and, for supported requests, `rag.answer`; RAG retrieves again inside its own contract. This is redundant retrieval, not an invented reuse optimization. Inspect the evidence channel and source IDs rather than assuming both stages retrieved identical context.

Run `uv run python labs/09_graph_workflows/main.py --check`. Use updates to identify the branch contributions and final state to inspect their merge. Both the retrieve and constraint events should survive before draft.

## Guided completion and diagnosis
Draw the graph before reading the edge declarations. Replace the barrier with an edge from only retrieve in your own copy and predict the dependency violation. Adding parallelism is safe only when branches are independent and the join expresses what downstream work needs. A reducer resolves competing updates; it does not create missing dependencies or authorization.
