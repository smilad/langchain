# 09.1 — State is a contract, not a bag of shared mutations

**In plain words:** A graph passes a state object between steps. Each step returns only the part it changes. Graphs suit fixed workflows where you want to see exactly what each step did.

[Mission](../../MISSION.md): make orchestration inspectable. **Objective:** reconstruct a request's state from node updates and explain why a graph is appropriate here.

## Mental model and flow
A `StateGraph` describes computation over named state channels. A node receives a snapshot, returns a partial update, and the runtime applies the update. An edge selects the next node. Compilation checks graph structure; it does not prove business correctness or termination.

The [lab](../../labs/09_graph_workflows/main.py) declares `RequestState`: question and user identity enter once; route, evidence and draft appear later; events accumulate. Its flow is:

| Stage | Reads | Writes |
|---|---|---|
| classify | question | route, event |
| retrieve | question, user_id | evidence, event |
| constraints | existing snapshot | event |
| draft | question/evidence | draft, origin, status, event |

Run `uv run python labs/09_graph_workflows/main.py --check`. The output exposes actual per-node updates and final state for three inputs. Compare your run with the captured output linked at the end. A supported fixture should finish drafted, an escalation should request human review, and Saturn should finish unsupported.

## Worked reasoning and guided completion
Notice that retrieve returns evidence and one event, not a mutated copy of the entire input. Keeping updates narrow makes responsibility visible. Predict which keys survive if classify returns only route. Then temporarily remove the retrieve-to-join edge in your own exercise copy; identify the missing dependency before changing anything else.

## Independent variation and failure diagnosis
Use [the exercise](../../exercises/09_graph_workflows.md) to add a new constraint branch. If a draft lacks evidence, inspect the updates and fan-in edge rather than modifying the model prompt. A graph is justified here by a prescribed workflow and inspectable dependencies; an open-ended agent loop would obscure that contract.
