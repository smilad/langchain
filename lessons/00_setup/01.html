00.1 — Choose the interpreter before choosing an API

Mission/objective: Support the course mission by reproducing the environment and showing which Python owns an import. No prior Python knowledge is assumed. Before starting, locate a terminal and the repository root; do not paste a credential into a command.

Sources/version: uv projects, Python virtual environments. Sources checked 2026-10-12; course requires Python ≥3.14. Installed authoring snapshot: Python 3.14.0, LangChain 1.4.4, Pydantic 2.14.1; exact resolution is in uv.lock. Consult verification for actual runtime evidence. No model capability or API key is needed.

Recall before reading

What is the difference between a directory name and an import name? If two Python installations exist, where does a package install go? Write a prediction, then use the separate solution.

Mental model and flow

The terminal launches an interpreter; that interpreter searches its import paths. An IDE can launch a different interpreter even while displaying the same files. A virtual environment isolates dependencies, not source code or credentials. pyproject.toml describes allowed dependencies; uv.lock records a specific resolution. Neither demonstrates that a provider integration works on your machine.

Boundary Input Output to inspect
uv sync --locked metadata + lock + selected Python installed environment
uv run python … script + project environment process and import paths
preflight running interpreter and installed metadata version, interpreter, import origin

Worked example

From the repository root:

uv sync --locked
uv run python labs/00_setup/main.py --check

These are implemented entrypoints, not an execution claim. Inspect interpreter, packages, and langchain_origin in the actual report. langchain must be the external framework; the course package is langchain_learning. Keeping the checkout directory named langchain is harmless; publishing a local package with that import name is not. The lab rejects an origin under the repository's src directory.

Guided completion and investigation

Select the lab's reported interpreter in your IDE, then rerun from the IDE yourself. Before comparing output, predict which field would expose a mismatch. Complete the explanation: “My editor's interpreter differs from uv run because ___; I will change ___, not reinstall packages randomly.” Diagnose ModuleNotFoundError by checking interpreter and installation first, not by renaming the external framework.

Transfer, exit, review

Attempt diagnostic tasks 1–2 in the exercise. Exit evidence is a reproduced environment, external import origin, and a teach-back of metadata versus lock versus installed files. Next session repeat with a fresh terminal; in Module 02 explain why provider integrations are separate distributions. See the lab runbook and troubleshooting reference. A useful follow-up question names both interpreter paths, never a secret.
