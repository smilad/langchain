00.2 — JSON and configuration are untrusted input

In plain words: Data that arrives as JSON text is not yet trustworthy. First you parse it (is the syntax valid?), then you validate it (does it have the fields and types you need?). Each step fails differently, and you should handle the failures separately.

Mission/objective: Advance the mission by writing a typed JSON boundary that rejects bad records without exposing environment values. Prerequisite: 00.1; check that you can explain which Python executes your script.

Sources/version: Python JSON, exceptions, environment access. Checked 2026-10-12; installed authoring snapshot Python 3.14.0/Pydantic 2.14.1. Exact resolution is in uv.lock; actual execution evidence is in verification. Entire lesson is local and unpaid.

Mental model

JSON is a serialized value, not a trusted Python object. json.loads can return a list, number, dictionary or null. A function annotation documents an expectation but does not enforce it. Parsing syntax and validating the application contract are different stages, and their exceptions identify different repairs.

The lab gives the complete boundary:

def read_request(raw: str) -> Request:
    return Request.model_validate(json.loads(raw))

The control flow is str → JSON value → Request → consumer. Malformed JSON stops at the decoder. A dictionary without request_id parses successfully and then fails validation. The return annotation tells a caller what successful execution provides; an exception means no Request was returned. Never catch every exception and return an invented default request.

Worked example and guided completion

Run the setup check. It parses {"request_id":"REQ-01","quantity":2}, serializes the validated model, and decodes that serialized JSON again. The lab also catches named invalid cases and prints error locations/types. These cases are synthetic diagnostics; the README does not claim the commands have already run.

Configuration follows another boundary: os.environ.get(name) → bool(value) → safe report. Supply the missing operation in a new small function that reports whether COURSE_MODEL is configured, not its contents. A presence check proves neither valid authentication nor a usable model. The shared loader reads .env without overriding an exported value, so an old shell variable may take precedence.
