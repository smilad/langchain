07.1 — Build two-step RAG before an agent

In plain words: Two-step RAG first retrieves allowed documents, then asks the model to answer from them. Doing it in two steps lets you inspect the evidence and the answer separately. With no evidence, the system abstains without calling a model.

Objective and prerequisites

course mission: Trace one question through retrieval and actual structured generation with separately visible evidence.

Prerequisite check: Modules 02, 03 and 06; explain a retriever result without asking a model.

Mental model

Two-step RAG fixes the order: retrieve authorized current documents, then supply those documents and the original question to a real model. It is a useful baseline because retrieval misses and generation failures can be inspected separately. PolicyIndex.as_retriever invokes the same retrieval boundary used by later workflow code. answer_with_evidence returns a GroundedAnswer, the exact Documents supplied, and local timing/usage metadata. answer returns only the typed result for consumers that already know their evidence-inspection path.

The model comes from get_model and is wrapped with with_structured_output(GroundedAnswer, include_raw=True). The schema contains answer, source_ids and abstained. Raw usage metadata is retained when the provider reports it; the raw model object or credentials are not printed. A parsing failure is an explicit error, not an invented completion. Nonempty evidence always takes the real model path. Empty evidence deterministically yields an honest abstention without making a provider call.

A system message states the answering contract; a human message serializes the question and evidence as distinct JSON fields. JSON helps delimit data but does not make prompt injection impossible. Current-version and audience checks occur before this prompt. MALICIOUS is visible as untrusted data and cannot be cited as an approved policy. The check lab only inspects evidence and deterministic invariants. It does not present a hand-authored answer as model-generated. Run live to obtain actual output and then review semantic support.

Data/control flow

Question + identity → authorized retriever → evidence JSON → real model/schema → citation checks → answer + trace

Worked example

Run from the repository root after uv sync --locked.

from langchain_learning.rag import answer_with_evidence
# Requires paid-call consent and configured model:
result = answer_with_evidence("What is the returns deadline?", "alice")
print(result["answer"].model_dump())
print([d.metadata["chunk_id"] for d in result["evidence"]])
