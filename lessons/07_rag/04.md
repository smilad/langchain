# 07.4 — Compare bounded agentic retrieval

**In plain words:** An agent can decide when and what to search, but that adds cost, variable latency and new ways to fail. Compare it with the plain two-step version on the same question and keep whichever is better supported.

## Mental model
Agentic RAG moves retrieval decisions inside a model-driven tool loop. The real create_agent instance receives a search_policies tool and ToolStrategy(GroundedAnswer). The agent may reformulate a query or search again; two-step RAG always retrieves once before generation. Extra flexibility introduces variable request count, latency and opportunities for evidence drift, so compare it with a baseline rather than assuming that an agent is an upgrade.

The tool closes over the authenticated user_id and PolicyIndex. The model supplies a query only, not an identity or an audience. Every invocation rechecks current authorized sources. Collected evidence is deduplicated by chunk ID and returned for inspection. A hard three-search budget and graph recursion limit bound execution; exhausted budgets raise an explicit error. ToolStrategy handle_errors=False avoids an invisible corrective-output retry loop in this comparison. If the agent never retrieves any evidence, the published result is an abstention, not an answer from model memory.

Citation membership is checked against actual trusted retrieved sources after the agent finishes. This does not prove claims are supported or resolve a contradiction across multiple searches. Read search traces, accumulated evidence and substantive claims. A model that fetches contradictory notices must still abstain. The agent has no write tool or finance permission bypass, and malicious source content cannot change the closure's identity.

The lab compares both architectures on the same question, user, strategy and k with actual live calls. Its one paired trial is demonstration evidence, not general superiority. Repeat a declared number of development trials, count reported model usage, and include failures instead of selecting the nicest run. An agent can legitimately lose to the simpler architecture; retaining the baseline is an engineering result.
