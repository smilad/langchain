01.3 — Inspect the response, not only the text

In plain words: A response holds more than text: a status, the model that answered, token usage and timing. This lesson makes one real call, which costs money, and has you inspect each of those parts.

Mission/objective: Advance the mission by executing one direct provider call when permitted and identifying request, response, timing and usage boundaries. Prerequisites: 01.2, a provider account, an explicitly chosen model and approved spend. Missing prerequisites block live evidence, not conceptual learning.

Sources/version: official OpenAI Python SDK, Responses API. Checked 2026-10-12; installed authoring snapshot Python 3.14.0/OpenAI SDK 3.29.0; exact resolution is in uv.lock. Verification records the author's live Responses output, timing, and tokens, not a certification of the public API. A Responses-capable model is required; there is no hardcoded model ID.

Retrieval warm-up

What is a 429? Why is a valid label not necessarily correct? Attempt before reading diagnoses.

Flow and worked example

The lab obtains secret-bearing settings only in --live, removes the model from constructor settings and creates an SDK client inside a context manager:

with OpenAI(**settings) as client:
    started = perf_counter()
    response = client.responses.create(**payload)
    elapsed = perf_counter() - started

Never print settings. The printable payload has only synthetic input, instructions, model ID and output budget. API credentials travel in authentication, not in the printed request body. The response report includes response ID, actual model, status, full output items, output text and provider-reported usage when present.

Elapsed time is a client wall-clock interval around the SDK call: it includes network and any permitted SDK retry, not only generation. The course permits at most one retry after the first attempt. Report missing usage as null; do not invent token counts or call token totals dollars without a dated price assumption.

Guided completion and real command

After independently choosing credentials/model/budget through the root setup instructions:

uv run python labs/01_llm_baseline/main.py --live --text "The sign-in page crashes."

This requests one classification, potentially billable. A live flag alone is insufficient: COURSE_ALLOW_LIVE=1 is also required. Before execution, fill the expected report columns without guessing their values. Afterwards copy only your actual synthetic result into your own evidence, distinguishing status, output text and validated label. No observed output is supplied here.

Failure investigation, transfer and exit

A non-completed response stops before label acceptance. Empty or unexpected output is an error, not a default other. Predict missing configuration, unavailable model, timeout, rate limit and contradictory rubric failures, then attempt the exercise. Exit by tracing every boundary and explaining which error class warrants changing a prompt.
