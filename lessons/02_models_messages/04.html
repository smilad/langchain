02.4 — Stream for display, aggregate for inspection

In plain words: You can call a model and wait for the whole reply, or stream it in pieces. Streamed pieces can be added together into the full message, and batch runs several inputs at once. Each mode has different cost and ordering behavior.

Mission/objective: Serve the mission by choosing invoke/stream/async/batch execution and reconstructing a streamed message without treating events as prose. Prerequisites: 02.3, async readiness. Live paths require consent, credentials and a compatible model.

Sources/version: model execution modes, message chunks, OpenAI streaming usage. Checked 2026-10-12; installed authoring snapshot Python 3.14.0, langchain-core 1.6.9/langchain-openai 1.7.0. Worked example and guided reconstruction

The lab displays chunk.text to stderr and adds whole chunks:

full = chunk if full is None else full + chunk

The accumulated message is then emitted separately with content blocks, tool calls and usage. An empty final chunk may contribute usage; never skip it just because it has no text. Some endpoints omit streaming usage; the runtime does not guarantee it. The check mode combines authored chunks containing bill, ing and a usage-only chunk. This verifies actual addition semantics, not generation.

Supply the missing accumulator step in your own copy, then predict what is lost by collecting only strings. For a real interactive view, --live --mode stream --interactive reads one synthetic input line and makes one request. No perpetual paid loop is hidden in the UI.

Failure investigation and variation

If a stream fails halfway, partial displayed text is not a completed validated answer. Do not save it as success. Batch output order follows input order, not completion order; this lab reports only aggregate batch duration and marks individual duration unavailable. Try the exercise with metadata-only chunks and a new technical input.
