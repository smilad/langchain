# 02.4 — Stream for display, aggregate for inspection

**In plain words:** You can call a model and wait for the whole reply, or stream it in pieces. Streamed pieces can be added together into the full message, and batch runs several inputs at once. Each mode has different cost and ordering behavior.

**Mission/objective:** Serve the [mission](../../MISSION.md) by choosing invoke/stream/async/batch execution and reconstructing a streamed message without treating events as prose. Prerequisites: [02.3](03.md), [async readiness](../00_setup/04.md). Live paths require consent, credentials and a compatible model.

## Mental model and execution table
| Mode | Boundary | Requests in this lab |
|---|---|---|
| invoke | messages → complete AIMessage | 1 |
| stream | messages → chunks → accumulated message | 1 |
| async | await messages → complete AIMessage | 1 |
| batch | two message lists → input-ordered responses | 2, concurrency capped at 2 |

`--mode all` runs all four paths, five requests total, with any permitted provider retry additional. LangChain client-side batch is not a discounted asynchronous provider Batch API. Concurrent calls can increase rate-limit pressure. Streaming reduces time until text is visible, not necessarily total cost or latency.

## Worked example and guided reconstruction
The [lab](../../labs/02_models_messages/main.py) displays `chunk.text` to stderr and adds whole chunks:
```python
full = chunk if full is None else full + chunk
```
The accumulated message is then emitted separately with content blocks, tool calls and usage. An empty final chunk may contribute usage; never skip it just because it has no text. Some endpoints omit streaming usage; the runtime does not guarantee it. The check mode combines authored chunks containing `bill`, `ing` and a usage-only chunk. This verifies actual addition semantics, not generation.

Supply the missing accumulator step in your own copy, then predict what is lost by collecting only strings. For a real interactive view, `--live --mode stream --interactive` reads one synthetic input line and makes one request. No perpetual paid loop is hidden in the UI.

## Failure investigation and variation
If a stream fails halfway, partial displayed text is not a completed validated answer. Do not save it as success. Batch output order follows input order, not completion order; this lab reports only aggregate batch duration and marks individual duration unavailable.
