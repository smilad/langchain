02.3 — Render inputs explicitly before calling the model

Mission/objective: Advance the mission by rendering a prompt and inspecting the separation between instructions and user data. Prerequisite: 02.2; distinguish a human message from a tool result.

Sources/version: ChatPromptTemplate reference, messages. Checked 2026-10-12; installed authoring snapshot Python 3.14.0/langchain-core 1.6.9. Exact resolution is in uv.lock; actual execution evidence is in verification. Rendering is local; only the subsequent model invocation can incur cost.

Retrieval warm-up

What is the model's input context in the baseline? Does a role make untrusted input safe? Try before feedback.

Mental model and flow

A template is a deterministic mapping from named values to a prompt value. It is not a model response. In this lab, a fixed system instruction defines the classifier and a human placeholder contains the learner's text. We inspect this intermediate representation before transport so missing variables cannot masquerade as model errors.

prompt = ChatPromptTemplate.from_messages([
    ("system", instructions), ("human", "{text}"),
])
rendered = prompt.invoke({"text": "I was charged twice."})
messages = rendered.to_messages()

The boundary is dict[str, str] → ChatPromptValue → list[BaseMessage] → model. invoke on a template renders; invoke on a model sends a request. Same interface name, different component responsibility. Naming every stage prevents accidental paid calls while debugging.

Worked example and fading

Run the check. It passes a user string containing literal braces {quantity} and an instruction-like phrase. Values inserted into the {text} slot are not recursively formatted as template syntax, so those braces remain user data. This prevents a formatting error, not prompt injection. The lab also invokes the template with wrong_name and catches the missing-variable KeyError before any remote client exists.

Complete a guided template with a second named context variable, render it locally, and inspect where the context is placed. Do not concatenate secrets or mix application policy into a user-provided string. If a history placeholder is introduced later, validate which messages are admitted rather than accepting arbitrary roles from untrusted users.

Failure investigation and independent variation

Predict whether changing {text} to {request} without migrating callers fails during template rendering or provider transport. Identify the actual required variable list rather than tweaking model temperature. Attempt the changed-label rubric and missing-input tasks in the exercise.
