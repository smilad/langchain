## Mental model and flow
`langchain` is not a bundle of every provider SDK. The integration `langchain-openai` supplies `ChatOpenAI`; `langchain-core` supplies messages, prompts and Runnable contracts. A common method such as `invoke` standardizes the Python interface, not every provider parameter or output type.

The [lab](../../labs/02_models_messages/main.py) calls shared `get_model()` only in its live path. Flow: `safe preflight → validate text → consent/configuration → ChatOpenAI → remote invocation → AIMessage inspection`. Constructing a client is not a demonstrated remote request. Check mode does not construct a model or infer successful credentials.

## Worked example and guided completion
The shared runtime's actual constructor is conceptually:
```python
ChatOpenAI(**model_settings(), temperature=0)
```
`model_settings()` contains a secret; never emit the dictionary or model object. Timeout is bounded, and one SDK retry is allowed. The selected model must accept temperature zero and the chosen endpoint's APIs. If it does not, document the incompatibility rather than assuming all model families are interchangeable.

Run `uv run python labs/02_models_messages/main.py --check` for real prompt/message operations only. Then write a three-row checklist matching each dependency to its responsibility. As a guided completion, identify the missing prerequisite before a live constructor is reached: a live flag without configured consent must stop, not select a fake model.
