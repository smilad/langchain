02.1 — Initialize an integration, not an imaginary universal model

Mission/objective: Advance the mission by creating a real LangChain chat-model client with explicit configuration and naming its capability assumptions. Prerequisite: Module 01; explain why low temperature does not guarantee correct classification.

Sources/version: models, ChatOpenAI integration. Checked 2026-10-12; installed authoring snapshot Python 3.14.0, LangChain 1.4.4, langchain-core 1.6.9/langchain-openai 1.7.0. Exact resolution is in uv.lock; verification records real gateway-mediated invocation. Paths still require compatible capabilities, private OPENAI_API_KEY, COURSE_MODEL, and COURSE_ALLOW_LIVE=1. Hosted tracing is optional and can transmit data; do not enable it implicitly.

Retrieve first

What does the SDK own versus the application? Which report field identifies an IDE mismatch? Attempt before consulting feedback.

Mental model and flow

langchain is not a bundle of every provider SDK. The integration langchain-openai supplies ChatOpenAI; langchain-core supplies messages, prompts and Runnable contracts. A common method such as invoke standardizes the Python interface, not every provider parameter or output type.

The lab calls shared get_model() only in its live path. Flow: safe preflight → validate text → consent/configuration → ChatOpenAI → remote invocation → AIMessage inspection. Constructing a client is not a demonstrated remote request. Check mode does not construct a model or infer successful credentials.

Worked example and guided completion

The shared runtime's actual constructor is conceptually:

ChatOpenAI(**model_settings(), temperature=0)

model_settings() contains a secret; never emit the dictionary or model object. Timeout is bounded, and one SDK retry is allowed. The selected model must accept temperature zero and the chosen endpoint's APIs. If it does not, document the incompatibility rather than assuming all model families are interchangeable.

Run uv run python labs/02_models_messages/main.py --check for real prompt/message operations only. Then write a three-row checklist matching each dependency to its responsibility. As a guided completion, identify the missing prerequisite before a live constructor is reached: a live flag without configured consent must stop, not select a fake model.

Failure investigation and independent variation

Predict the causes of an absent integration import, missing key, unknown model and unsupported sampling parameter. Installation problems are not prompt problems; a supplied key is not necessarily an authorized key. Attempt the configuration/capability variation in the exercise.
