# 02.2 — A message is an envelope, not always a string

**In plain words:** A message has a role (system, human, AI or tool) and content that can be plain text or several blocks. You will learn to pull out only the text meant for the user.

**Mission/objective:** Support the [mission](../../MISSION.md) by explaining a message sequence and distinguishing displayed text, content blocks, tool results and metadata. Prerequisite: [02.1](01.md); identify the package providing a provider client.

**Sources/version:** [official messages guide](https://docs.langchain.com/oss/python/langchain/messages). Checked 2026-10-12; installed authoring snapshot Python 3.14.0/langchain-core 1.6.9. Exact resolution is in `uv.lock`; actual execution evidence is in [verification](../../docs/VERIFICATION.md). Local message inspection needs no credential. Tool-call and multimodal capabilities vary by provider.

## Recall before reading
Can the provider output array contain more than text? Where does application conversation history live? Attempt before [corrections](../../solutions/02_models_messages.md).

## Mental model and worked sequence
System messages carry instructions, human messages carry user input, AI messages carry model responses or explicit application-authored history, and tool messages carry execution results linked to a tool-call ID. A tool message is not evidence that the assistant's prose is true. A message role is not an authorization decision.

| Attribute | What to inspect |
|---|---|
| `content` | raw string or blocks, possibly provider-specific |
| `text` | text projection for display |
| `content_blocks` | normalized block types |
| `tool_calls` | requested function names/arguments/IDs |
| `usage_metadata` | optional reported counts |

The [lab](../../labs/02_models_messages/main.py) builds an explicitly hand-authored AIMessage with a text block and a reasoning block, then checks that only visible text is displayed. This is a data-structure fixture, not a fake model. It also constructs a ToolMessage with a call ID and JSON text; nothing executes a tool in this module.

## Worked example and guided completion
```python
message = AIMessage(content=[
    {"type": "text", "text": "Visible text"},
    {"type": "reasoning", "reasoning": "Authored example"},
])
```
Use the setup check to inspect the raw content and text projection. Predict why `str(message.content)` is unsuitable as a user-facing answer. Complete an inspection table for one real response, if live access is available, without assuming reasoning blocks or usage will be present. Null usage means unavailable, not zero.

## Failure investigation and variation
A renderer that concatenates every dictionary could expose metadata or produce nonsense; a renderer that treats a tool call as prose misses execution semantics. In the [exercise](../../exercises/02_models_messages.md), introduce an empty text block and a tool-result envelope. Explain each object's provenance. Do not label an authored AIMessage as observed generation.
