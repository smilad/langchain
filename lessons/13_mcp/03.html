13.3 — Expose only the capabilities you intend

In plain words: Expose only the tools you intend. A read-only label is a hint, not a lock, so each tool still validates its inputs and has no way to write files or run commands.

Mission/objective: advance the mission by explaining and enforcing the local server's capability and credential boundary without claiming protocol-level security immunity.

Prerequisites: current adapter, argument validation, and synthetic-data handling. Check: identify the trusted executable and the untrusted argument in a tool invocation.

Sources/version: MCP tools and metadata, FastMCP server configuration, and client transports, checked 2026-10-12. Python 3.14.0, LangChain 1.4.4, FastMCP 4.1.0; beta adapter behavior is version-sensitive. See verification for exercised evidence. The local server requires no model or production credentials.

Recall before reading

Does readOnlyHint prevent file writes? Does a connected server become trusted? Correction after an attempt: annotations are declarations, not enforcement; connection authenticates/negotiates transport, not the truth or safety of arbitrary tool behavior.

Mental model

The server registers only catalog_lookup and catalog_quote. Their Python implementations delegate to real catalog functions with bounded identifier and strict quantity validation. They read synthetic JSON and perform integer arithmetic. No shell, arbitrary file path, purchasing operation, workflow decision, or secret-reading capability is registered.

untrusted arguments → schema checks → domain validation → read-only catalog operation

Both layers matter. FastMCP strict schema validation rejects mismatched types at the transport boundary; catalog validation protects direct Python callers too. The annotations document intent, while code and operating-system permissions determine actual capability.

Worked example

Inspect mcp_server.py. Errors are masked before returning tool details; the lab still records success/error status. The stdio server uses the client's subprocess lifecycle and needs no network bearer token. Do not add an API key merely because some remote MCP tutorials contain one. Do not commit credentials to MCP configuration or print inherited environment variables.

Run the model-free check and explain why quantity=0 should fail while an absent item should return explicit unavailable data. Then supply the missing allowlist check in a private client copy: unexpected advertised tools must stop discovery, not silently enter the agent context.

Independent change, diagnosis, exit

Follow the exercise with a changed stock case. If an unexpected tool appears, inspect registration/discovery before adjusting the model prompt. Exit by naming a capability this server cannot perform and the code enforcing that fact. Review least privilege in Module 14; ask whether the same assumptions hold for a remote unreviewed server. Solutions explain why read-only metadata alone is insufficient.
