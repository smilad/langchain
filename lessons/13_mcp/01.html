13.1 — MCP is a protocol boundary, not a trust certificate

Mission/objective: advance the mission by tracing a real catalog lookup across MCP and separating client, server, model, and tool responsibilities.

Prerequisites: catalog tools, security boundaries, and basic async. Check: explain what code actually executes after a model requests a tool.

Sources/version: LangChain MCP and FastMCP server, checked 2026-10-12. Authoring baseline: LangChain 1.4.4 with mcp extra and FastMCP 4.1.0 on Python 3.14.0; verification separates installed packages from exercised behavior. langchain.mcp is beta and may change. Local checks need no model credentials; live mode incurs provider calls.

Retrieve prior knowledge

Does a tool docstring authorize access? Is a tool result a model answer? Correction after an attempt: descriptions help selection, while authorization is code; a result is external data, not a guarantee of a supported final reply.

Mental model and flow

The server advertises read-only catalog capabilities and executes typed functions. The client negotiates protocol support, discovers tools, and sends calls. MCPAdapter converts the discovered tools into LangChain tools. A model is optional: ordinary Python can choose and invoke an adapted tool directly.

Python/agent → adapted tool → stdio client → FastMCP subprocess → catalog JSON → MCP result → ToolMessage

Tools are invocable operations. Resources are addressable data. Prompts are reusable templates. The course intentionally exposes only two tools; adding resource and prompt examples is not necessary to prove a real tool integration.

Worked example

Run uv run python labs/13_mcp/main.py --check. The adapter launches an actual subprocess, discovers catalog_lookup and catalog_quote, invokes real lookups/calculation, and inspects structured artifacts. Missing absent is a successful protocol call with a domain-level unavailable result. Quantity zero is a server-reported tool error. Neither is automatically a transport failure.

Guided completion and independent change

Draw the serialization boundary and label which process reads data/catalog.json. Supply the omitted distinction between ToolMessage.content and its structured artifact. Then use the exercise to change an item/quantity without granting write capability.

Failure investigation and exit

Predict the effect of printing debugging prose to server stdout: it can corrupt stdio protocol messages. Use stderr for operational diagnostics. Exit by showing a real client/server result and explaining why connection success does not imply trust. Review this boundary in production configuration; consult the glossary for transport and capability.
