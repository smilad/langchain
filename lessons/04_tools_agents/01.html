04.1 — Make a tool contract enforceable

Objective and prerequisites

Support the mission by defining a tool whose arguments are validated before local execution. After Module 03, explain why a valid JSON object can still contain an impossible business request. Warm-up: does a type hint validate an ordinary Python call? Does a tool description grant filesystem permission? Attempt both before reading the corrections below.

Sources/version: LangChain tools, consulted 2026-10-12. Python 3.14 and locked local tool checks are exercised; see versions and limits. Local calls need no credentials. Agent tool selection remains a live gate requiring a configured tool-capable model, consent, and possible charges.

Mental model: three distinct checks

A description helps the model choose a capability. The input schema constrains its arguments. The function enforces catalog invariants. None substitutes for the others. Our capability surface is only lookup and quote: there is no file-writing tool, checkout operation or arbitrary expression evaluator.

Boundary Input Responsibility
Schema item_id, optional quote quantity Exact ID shape; reject unknown fields; strict integer 1–20
Data loader Actual JSON records Validate records and unique identifiers
Quote body Valid quantity and found item Check stock; multiply integer cents

catalog.py uses explicit Pydantic models. QuoteInput extends LookupInput, and the LangChain tools receive these models through args_schema. The domain functions validate again because direct Python and MCP callers also exist. This deliberate boundary check is not a compatibility shim.

Worked example

Run the lab, or inspect this smaller fragment:

from langchain_learning.catalog import catalog_tools
lookup, quote = catalog_tools()
print(quote.args_schema.model_json_schema())
print(quote.invoke({"item_id": "notebook", "quantity": 2}))

The fixture contains a notebook at 1299 USD cents. Two units therefore quote 2598 cents; this is a calculation from committed data, not an observed execution transcript. True, "2", 1.5, zero and 21 are invalid quantities. Strictness avoids surprising coercion, including Python's boolean-as-integer behavior.

Complete, vary, diagnose

Guided completion: remove the stock comparison from a copy of quote_total; supply it before multiplication. Explain why a range-valid quantity can still exceed stock. Independent variation: attempt the stock-boundary cases in the exercise before opening its solution.

Predict what happens with an extra path argument. Inspect the validation error category, not just its rendered string. A schema rejection differs from found=false, which is a valid lookup outcome. Likewise, insufficient stock is a domain result, not a provider outage.

Exit and review

Demonstrate a valid quote and one invalid input; explain both validation layers and identify the stage that failed. Revisit strict integer behavior during Module 13's MCP exposure. Warm-up corrections: Python hints alone do not validate ordinary calls; docstrings are model guidance, never authorization. Reference: API map, next lesson.
