## Mental model
Offline evaluation replays declared cases under a recorded configuration; monitoring observes new real traffic under changing conditions. A twenty-case synthetic benchmark teaches failure classification but cannot establish population-wide production reliability. The CLI reports every case, category, evidence, error, trace and pending semantic review. A summary lists failure counts, reviewed rows and elapsed-time mean/population standard deviation. Read category-specific failures before averaging: no aggregate score can compensate for a data leak.

--trials declares repeated runs before execution. Each row retains its trial number and reported usage, allowing a learner to inspect answer variability rather than select the best completion. Timing variation includes provider/network/index effects. The first semantic search builds embeddings, while later searches reuse that identity's process-local store; label that warm-up asymmetry when comparing latency with lexical search. Provider token accounting may not include embedding requests, and absent usage remains unavailable. The report deliberately does not invent currency costs. If estimating costs, state pricing date, model rates, embedding charges and assumptions separately.

For lexical versus semantic comparison, fix user, model, k, cases and trials and use --compare-strategy semantic. Freeze both strategies on development before held-out review. Retain regressions and report missing evidence independently from unsupported answers. The evaluator neither chooses a winning design nor tunes parameters. One improved paraphrase case might justify further study but does not prove broad superiority.

Monitoring a deployed workflow requires permitted data retention, redacted logs, privacy review, operational error rates and workload-derived thresholds. An offline JSON report is not that monitoring system. Module 14 introduces request/service concerns; Module 15 asks for an honest architecture decision supported by actual measurements. Until live calls and human review occur, label those dimensions unverified rather than calling a clean deterministic run a production gate.

## Data/control flow
`Declared cases/trials → baseline + one alternative → per-case evidence/outcomes → human review → limited engineering decision`
