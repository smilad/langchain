08.1 — Read traces as causal evidence

In plain words: A trace shows what happened at each step: retrieval, model call, parsing. When an answer is wrong, find the earliest step that failed instead of editing the prompt.

Objective and prerequisites

course mission: Locate retrieval, model, tool and parsing failures without mistaking a final answer for a full trace.

Prerequisite check: Project A tool messages and Project B evidence inspection.

Sources and execution status

Primary: RAG evaluation tutorial. Documentation checked 2026-10-12. Installed baseline: Python 3.14.0, LangChain 1.4.4, core 1.6.9, OpenAI integration 1.7.0, Pydantic 2.14.1. Installation is not execution evidence; consult verification. Local lexical/check paths need no credentials. Live paths require explicit consent and paid provider access; semantic search additionally requires an embedding model, generation requires structured-output capability, and agentic comparison requires tool calling.

Recall before reading

Which event proves Python executed a tool? Can token count alone explain a bad answer? Attempt both questions before consulting the mental model; compare your reasoning afterward rather than copying definitions.

Mental model

A trace is the execution structure behind an output: retrieval precedes generation in two-step RAG, while agentic RAG alternates model calls and tool results. A final fluent answer hides this structure. Start with the question, caller identity, strategy and corpus fingerprint, then inspect actual selected chunks. Next inspect generated output, parsing/citation validation and timings. Only then decide whether the defect belongs to retrieval, generation or an execution boundary.

The course produces local JSON telemetry without requiring a hosted account. Two-step traces include retrieval_seconds, generation_seconds, total_seconds, model_calls and reported usage. Agentic traces additionally list each query and retrieved chunk IDs. Evaluation rows retain exact evidence even if generation subsequently fails. Error types are explicit without publishing provider configuration or raw secret-bearing exceptions. A trace of an abstention with zero model calls is deterministic evidence, not a completed provider demonstration.

Hosted LangSmith tracing can give nested run trees and model/tool details, but it can also upload question and evidence content. It is optional: decide whether the synthetic corpus may be uploaded before setting tracing variables, and never reuse that decision for private material. Local elapsed time includes process/index/provider work; it is not isolated model server latency. Provider usage may be absent and must remain unknown rather than zero. Trace IDs and response IDs help correlate actual runs; do not invent them.

Read one failure backwards: missing expected evidence is a retrieval miss; valid retrieval followed by an unsupported claim is a semantic generation defect; invalid citations are output validation failures. Record the earliest violated contract and avoid repeatedly tweaking prompts when the correct passage was never selected.

Data/control flow

Retrieval run → generation child → structured parser → membership validation; agentic runs also contain tool children
