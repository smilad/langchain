08.3 — Separate deterministic checks and semantic graders

In plain words: Some checks are exact (is the cited id valid, did it abstain). Others need judgment (is the claim supported). A model judge is fallible and should be checked against human ratings.

Objective and prerequisites

course mission: Score source membership separately from claim support and calibrate any model judge against humans.

Prerequisite check: Module 07 citations/abstention and Lessons 01–02.

Sources and execution status

Primary: RAG evaluation tutorial. Documentation checked 2026-10-12. Installed baseline: Python 3.14.0, LangChain 1.4.4, core 1.6.9, OpenAI integration 1.7.0, Pydantic 2.14.1. Installation is not execution evidence; consult verification. Local lexical/check paths need no credentials. Live paths require explicit consent and paid provider access; semantic search additionally requires an embedding model, generation requires structured-output capability, and agentic comparison requires tool calling.

Recall before reading

Can a citation check prove entailment? Can two models share the same mistaken interpretation? Attempt both questions before consulting the mental model; compare your reasoning afterward rather than copying definitions.

Mental model

The evaluator has three deliberately distinct layers. Deterministic retrieval checks verify current authorized metadata and expected-evidence recall. Deterministic output checks verify source membership and whether abstention matches the case label. Semantic support is explicitly not a deterministic check. A row can pass membership and still contain a wrong number, omit a condition, or resolve conflicting policies without evidence. Expected abstention labels are teaching targets, not substitutes for reading a nuanced response.

Human review scores groundedness, relevance and correctness from 0 to 2, records abstention appropriateness, and maps substantive claims to quoted evidence. A reviewer must consider source revision, access boundary, units and conditions, not just stylistic confidence. Supply reviewer identity and rationale; do not auto-fill a human judgment from the model's grade. The README describes the optional JSON review format. Unreviewed fields remain null rather than invented passes.

--judge adds a real paid structured-output model grader. Its grade, rationale, usage and elapsed time appear separately from generation and human review. The grader sees the question, rubric, actual answer and supplied evidence. The instructions require claim-to-evidence mapping, but those instructions do not make it an oracle. The same provider may share biases with the answer model, and malicious documents may also target the evaluator. No grader feeds an automated correction loop.

Calibrate on development examples: independently rate actual outputs, compare dimensions and record disagreement. A false positive on the human-authored 900-day example should trigger investigation of the judge, not changes to the human rubric. Inspect multiple runs when grading variability matters. For held-out reporting keep the frozen configuration and treat both grader and human disagreement as review evidence, not an excuse to tune until a favorable score appears.

Data/control flow

Actual result/evidence → deterministic checks; independently → human rubric; optionally → fallible paid model opinion

Worked example

Run from the repository root after uv sync --locked.

# Adds real grader calls; requires live consent:
uv run python labs/08_evaluation/main.py --live --judge --trials 2
# Human grades are supplied separately, never generated by this command.

Use the module lab to inspect actual intermediate values. Predict the result first and preserve any disagreement as a diagnostic clue.

Guided completion and failure investigation

Rate one actual claim before reading the model grade. Quote evidence for each dimension, then name a disagreement and a plausible evaluator failure mode.

Independent transfer and exit check

Take a changed constraint from the exercise without copying the worked example. Publish per-case source checks, human semantic findings and model opinions separately. Explain why a judge pass cannot erase an authorization failure.
